# 织思 Weave · 第二版交互原型

黑紫色的「探索与执行工作台」：同一张思维图中管理对话分支、执行代理、运行记录点和人工验收。

## 立刻查看

直接用 Chrome 或 Edge 打开 `index.html`，即可进入**演示模式**。不需要安装依赖，也不会启动外部 CLI。旧版保存在 `v1.html`。

建议按这条路线体验：

1. 在中央图谱点击任意节点；点击节点右上角的 `＋/−`，独立展开或折叠子分支。
2. 拖动空白画布、滚轮缩放，使用右下角小地图或顶部「定位」「全图」。
3. 选中节点后，在右侧修改 Prompt 和模型；点击「添加子分支」生成新节点。
4. 在「演示运行」模式分发任务，观察水流沿连线移动、节点进度和左侧小树逐渐生长。
5. 到「运行日志」「Checkpoint」查看模拟过程，记录快照并人工验收。

演示数据与新增节点保存在当前浏览器的 `localStorage`。右下角「重置示例」会清除这份 V2 演示数据。

## 连接本机 Claude Code

在此目录打开 PowerShell，执行：

```powershell
node server.mjs
```

然后打开 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。页面右上角会显示本地 CLI 是否可用。选择一个未在运行的节点，把「执行方式」切换为「本地 Claude Code（真实）」，检查 Prompt、模型和权限模式后点击「分发给执行代理」。

本地桥接固定绑定 `127.0.0.1`，同源托管页面及其 CSS/JS。真实任务只在用户点击分发后启动；桥接一次只接受一个正在运行的 Claude 任务。浏览器直接打开的 `file://` 页面只能演示，不能发送真实任务。

真实任务面板显示进程状态、输出事件与退出码，可请求取消。Checkpoint 是**运行证据快照**（状态、时间、会话 ID、日志尾部），不包含代码回滚。验收结论由用户手动记录；退出码为 0 只表示进程正常结束，不能单独证明成果满足需求。

本机需要已安装并登录 Claude Code。若 CLI 无法运行，右侧日志会显示错误。桥接服务重启后会清空内存中的任务记录；浏览器中的图谱节点仍保留。

- `weave-v2.css`、`weave-v2.js`：视觉与交互。
- `server.mjs`：本地 Claude Code 桥接。
- `产品文档.md`：第二版产品说明。
- `v1.html`：第一版原型。
